# Картка проєкту SmartBite

## 1. Назва

**SmartBite** - застосунок для планування харчування на основі персональної добової норми та продуктів, наявних у користувача.

## 2. Склад команди та відповідальність учасників

| Учасниця           | Зона відповідальності                                                                                                                                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Лопушанська Каріна | серверна частина (ASP.NET Core Web API), модель даних і доступ до даних (Entity Framework Core), модуль розрахунку норм, щоденник харчування, неперервна інтеграція, ведення переліку завдань |
| Климкович Сандра   | настільний клієнт (WPF), проєктування інтерфейсу, інтеграція з OpenRouter (генерація рецептів, оцінка калорійності), аналіз вимог, стратегія тестування                                       |

Розподіл відповідальності визначає, хто відповідає за результат у кожному напрямі, але не обмежує участь в інших частинах проєкту. Кожна учасниця бере участь у плануванні, обговоренні технічних рішень і перегляді коду іншої учасниці.

## 3. Проблема

Контроль харчування передбачає два регулярні завдання: визначення кількості спожитих калорій і макронутрієнтів та вибір страв, що відповідають добовій нормі. Під час їх виконання виникають такі труднощі.

1. **Трудомісткість ручного обліку.** Для внесення страви до щоденника користувач має знайти кожен інгредієнт у базі продуктів, визначити його масу та вручну скласти запис. Для страв із кількох компонентів це займає кілька хвилин на один прийом їжі, що знижує регулярність обліку.
2. **Відсутність зв'язку між наявними продуктами та нормою.** Вибір страви з продуктів, які є вдома, зазвичай здійснюється без урахування того, скільки калорій і макронутрієнтів залишилося до добової норми. Якщо користувач не знаходить відповідного варіанта, він частіше обирає готову їжу, а частина продуктів залишається невикористаною до завершення терміну придатності.
3. **Орієнтація наявних рішень на мобільні пристрої.** Поширені застосунки для обліку харчування розроблені передусім для смартфонів. Користувачі, які проводять більшу частину дня за комп'ютером, не мають окремого настільного засобу, у якому облік харчування поєднано з добором рецептів.

## 4. Цільові користувачі

| Група                                               | Характеристика                                                  | Потреба                                                                |
| --------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Люди, які контролюють масу тіла                     | мають визначену мету: зниження, підтримання або набір маси тіла | знати добову норму КБЖВ і дотримуватися її без значних затрат часу     |
| Студенти та працівники з віддаленим форматом роботи | більшу частину дня працюють за комп'ютером, готують їжу вдома   | планувати харчування з робочого комп'ютера без переходу на смартфон    |
| Користувачі без досвіду планування харчування       | не мають навичок складання раціону з наявного набору продуктів  | отримувати готовий рецепт із поясненням кількості інгредієнтів та КБЖВ |

Застосунок не призначений для людей, яким харчування визначає лікар відповідно до медичних показань. Розрахунки та рекомендації мають довідковий характер.

## 5. Мета

**Мета проєкту** - розробити настільний застосунок для ОС Windows, який скорочує час, необхідний для обліку харчування, та допомагає обирати страви з наявних продуктів відповідно до персональної добової норми КБЖВ.

Для досягнення мети необхідно виконати такі завдання:

1. реалізувати розрахунок добової норми КБЖВ за формулою Міффліна - Сан Жеора з урахуванням рівня активності та мети користувача;
2. реалізувати облік продуктів, наявних у користувача;
3. реалізувати генерацію рецептів із наявних продуктів з урахуванням залишку добової норми з використанням мовної моделі через OpenRouter;
4. реалізувати оцінку калорійності страви за фотографією або текстовим переліком інгредієнтів з використанням моделі Gemini;
5. реалізувати щоденник харчування з денним підсумком відносно норми;
6. забезпечити перевірку якості продукту автоматизованими тестами та неперервною інтеграцією.

## 6. Основні можливості

| Можливість                | Опис                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Розрахунок добової норми  | визначення норми калорій, білків, жирів і вуглеводів на основі віку, статі, зросту, маси тіла, рівня активності та мети                        |
| Облік наявних продуктів   | ведення переліку продуктів із кількістю, одиницею виміру, категорією та терміном придатності                                                   |
| Генерація рецептів        | формування рецепта з вибраних продуктів: перелік інгредієнтів із масою, кроки приготування, КБЖВ порції та частка добової норми                |
| Оцінка калорійності       | визначення складу страви та орієнтовного КБЖВ за фотографією або текстовим переліком інгредієнтів із можливістю ручного коригування результату |
| Щоденник харчування       | фіксація прийомів їжі, денний підсумок спожитих КБЖВ і залишок до норми                                                                        |
| Аналітика та рекомендації | динаміка споживання за тиждень і місяць, рекомендації щодо харчування на основі записів щоденника (після MVP)                                  |
