# Перелік завдань

## 1. Структура переліку

- Завдання згруповані за етапами роботи над проєктом. У GitHub Projects кожна група відповідає віхі (milestone), а кожне завдання - окремому issue.
- Для кожного завдання вказано відповідальну учасницю, пріоритет і стан.
- Пріоритет: **високий** - потрібно для MVP; **середній** - бажано зробити після основних функцій; **низький** - якщо залишиться час.
- Стан: Заплановано → В роботі → На перегляді → Виконано. Ці стани відповідають колонкам дошки.

## 2. Порядок виконання

Групи виконуються по черзі. Усередині групи спочатку беремо завдання з високим пріоритетом. Клієнт OpenRouter робимо якомога раніше, бо це найменш передбачувана частина проєкту: якщо з відповідями моделей будуть проблеми, краще дізнатися про це на початку.
